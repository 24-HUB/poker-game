# Account Email Codes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after owner review. Steps use checkbox syntax for tracking. Native execution is proposed; no delegation has been authorized.

**Goal:** Replace verification and password-reset links with emailed, single-use six-digit codes while preserving existing accounts and requiring password sign-in after success.

**Architecture:** Keep Better Auth 1.7.6 for registration, password hashing, sign-in and uncached sessions. Add a dedicated MongoDB challenge service and a native-response auth handler for the four approved operations, rather than mount the OTP plugin's additional routes. Share a persistent per-address serialization document between issuance and confirmation, and include challenge, credential, verification and session writes in one replica-set transaction.

**Tech Stack:** Existing NestJS/Express, MongoDB official driver, Next.js/React, Zod, Jest, Vitest, Playwright, Node 22 and pnpm 10.33.0. No dependency changes planned.

**Spec:** [Account email codes](../specs/2026-10-12-account-email-codes.md).

**Execution status:** Owner explicitly directed immediate implementation on 2026-10-13. Native execution is underway on `codex/account-email-codes`, starting at `origin/dev` `bf472463`, with draft PR #27. Local implementation and verification evidence are recorded in `CHECKPOINT.md`; hosted acceptance is separately authorized work.

## Global constraints

- Code lifetime 600 seconds; six decimal digits including leading zeroes; latest generation only; no immediately repeated or simultaneous cross-purpose identical code for an account.
- Five wrong attempts; the fifth invalidates the challenge and a correct sixth fails. Failed outcomes commit before their HTTP error is returned.
- Database-enforced 60-second issuance cooldown and five issuances per normalized email/purpose per hour, including signup. Maximum 20 send attempts per trusted IP/hour and 30 confirmation attempts per trusted IP/10 minutes. Return 429 and `Retry-After` without disclosing account existence.
- HMAC-only challenge storage with domain-separated key derived from `BETTER_AUTH_SECRET`; no plaintext codes, passwords or tokens in logs, URLs, browser storage or traces.
- Preserve registration-code authorization, account IDs, wallets, cosmetics, trusted proxy/public origin checks, test-only capture and 8–128 character password policy.
- Verification creates no session. Reset also verifies email, revokes every older session and invalidates both purposes; it creates no session.
- Legacy GETs only redirect to a clean request-code surface; legacy POSTs and all unapproved OTP routes are unavailable. Never re-enable them in rollback.
- Prepare additive migration locally; no deployment, live database operation, provider update, merge or paid upgrade is authorized. Every task change uses a PR targeting `dev`; the owner merges manually.

## Review focus

1. Email aliases/case and invalid input must not split budgets or alter another account; test normalization through native signup and recovery.
2. Transaction callback retries must not generate or send additional codes; test a retry and assert one committed generation/one delivery.
3. Successful reset racing verification issuance must invalidate stale generations; test both serialization orders, including an unverified account.
4. Unknown addresses during a delivery outage must receive the same externally observable request result as known addresses; test native response status/body and no false delivery claims.
5. A closed or changed form must ignore late asynchronous results without restoring cleared secrets or changing the new email's state; test deferred responses and modal reopen.
